# Requirement Baseline

Use this compact working copy only when a Requirements Analyst is clarifying
material business ambiguity. It is optional local evidence, not a routing,
review, or OpenSpec status. When an active OpenSpec change exists, OpenSpec
remains authoritative; link this file rather than copying it into handoff. If
a later OpenSpec change adopts this evidence, it supersedes or explicitly
reconciles the baseline before downstream work relies on it.

Use this baseline to record problem-space quality challenges: coherence between
goal, actors, desired behavior, and must-haves; user/business value and observable
acceptance; contradictions, missing business rules, and unintended effects; data
availability, data authority, and decision ownership; and operational burden or
obvious business infeasibility. Mark technical claims as assumptions for Chief
Designer. Do not choose architecture, APIs, schemas, or technical disposition.
