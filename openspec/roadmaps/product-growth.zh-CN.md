## 产品方向

## 阶段安排

| 阶段 | 最小成果 | 推进条件 |
| --- | --- | --- |
| 当前：补齐首次体验 | 一个固定虚构任务、双语指南、两个新目录的真实 A/B 接续和独立维护审查 | 以当前正式变更本地验收为准；尚未实施或没有证据的项目不写完成 |
| 外部 G0 | 三位未参与设计的目标用户首次试用，至少两位无额外辅助完成，内部两次复现和关键保护成立 | 人数或条件不足标外部待验证；内部复现成立时可进行有限内部 Phase 1 |
| 有限 Phase 1 | 一次编码中途新会话接续、一份符合实际风险的独立审查，再尝试一个有实际用户的跨工具组合 | 记录版本、输入、结果与限制；不能由同宿主结果推断跨工具兼容 |
| Phase 2 | 每次选择一个可复现的主要障碍，累计最多两项局部改进，或有依据地不增加功能 | 比较现有替代、最小改动、检查、维护成本与回退；修后复测原痛点 |
| Phase 3 | 可使用的反馈入口、少量真实贡献任务和可承担的维护节奏 | 根据实际反馈与维护容量安排，不以 Issue、PR 或功能数量凑门槛 |

F3 SetMode 失败恢复优先安排独立最小修复。F4 可信 v2 布局演进须在新增／退役受管路径的发行前解决；本次源码专用样例不增加受管路径。后续具体实施另立范围，不混入演示验收。

## 首次体验的分发与状态

源码样例、完整安装包、演示目标分开。样例从含该样例的固定 Git 提交检出；完整 v1.10.1 包另从可信发行取得。样例被 export-ignore 排除，不能承诺 GitHub 自动 Source code ZIP 或完整安装包包含它。未提交候选可用文件指纹做本地演练，真实公共 SHA 与取得入口在授权提交准备时再核对。

本地 accepted 只涵盖映射的交付。公开获取未核对时保留待验证；外部 G0 未开展时也保留待验证。十分钟只是准备就绪后的核心体验目标，完成门槛与耗时分别报告，不作普遍承诺。

## 最小试用记录

采用匿名编号，记录版本／环境、首次或重试、标准操作与额外救援、结果、核心和完整耗时、最难一步及再次使用意愿。复制实时 Operator Command 属于标准操作；补讲需求、代操作或修改输入属于额外辅助。保留首次失败、退出和修订后重试；没有数据写未测。内部 Agent 演练不计外部用户。

默认不收集遥测。原始聊天、真实运行态、安装备份与私人路径留在本地；公开仅使用必要脱敏摘要。外部联络、真实项目与公开材料仍需适用授权。

## 上游借鉴与投入

本轮固定来源与兼容性取舍见[正式设计](../changes/archive/2026-10-31-improve-first-handoff-trial/design.md)。采用 Superpowers 的行为取证、CE 的简短引用与现有经验复用、GSD Core 的分层文档组织思想；本轮不导入上游功能或整套生命周期，不新增运行时、状态库或机器字段。工程师无需重复研究整套上游。

上游比较时间盒为 2～3 小时；首批样例、指南和内部演练建议控制在 6～10 小时有效投入，模型等待和外部招募另计。估算仅作投入参考。显著超预算或遇到低收益大投入时，说明已取得证据、更小方案和建议，再决定是否扩张。
