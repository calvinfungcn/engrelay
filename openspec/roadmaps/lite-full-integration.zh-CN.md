# EngRelay Lite／Full 整合实施路线

[English](lite-full-integration.md)

基线：EngRelay v1.9.6；输入参考：用户提供的 Lite 0.2.0。本文为已选方向的实施规划，不代表功能已交付。参考材料只作输入，不成为第二份产品规范。

## 分期与实施入口

总共三期，顺序推进。第一期交付可审阅的协议设计；第二期交付可在隔离目录安装的实现；第三期交付经演练和审查的发行候选。三期是里程碑，不要求各发布一个版本。

| 期次 | 目标 | 核心交付物 | 完成判据 | 相对投入 |
| --- | --- | --- | --- | --- |
| 第一期 | 确定 Lite 的行为与兼容边界 | 短协议设计、交接字段、场景样例、安装与旧清单转换设计 | 设计无待定的关键兼容决定，样例覆盖正反路径，必要独立设计审查通过 | 中 |
| 第二期 | 实现两种配置及共用管理器 | Lite 规则／模板／校验工具、配置安装与维护、清单转换、诊断、基础双语指引 | 两种配置在一次性夹具中可分别安装、升级、诊断和卸载，保护检查通过 | 高 |
| 第三期 | 验证使用体验并完成发行准备 | S/M/H 与接续演练证据、修复、完整人类说明、独立审查与候选包证据 | 对应验收、所需审查与独立验证完成，未测范围披露，候选清单与字节一致 | 中 |

正式变更：[integrate-lite-full-profiles](../changes/archive/2026-10-24-integrate-lite-full-profiles/proposal.md)。三期仅在该变更的 [tasks.md](../changes/archive/2026-10-24-integrate-lite-full-profiles/tasks.md) 维护实施勾选；本文说明目标与验收，不同步复制完成率、Review 轮次或运行态。

实际实施及审查证据见已归档变更的 tasks.md 和[审查索引](../../docs/reviews/integrate-lite-full-profiles/index.md)。规划工件齐全或单期设计验收不代表产品或三期已经完成。

## 共同产品决定

1. 同一仓库、统一版本、一个完整发行包、两个固定配置。新参数名为 `WorkflowProfile`，取值 `full|lite`；这是拟实现接口，当前 v1.9.6 尚不支持。
2. `WorkflowProfile` 选择规则与安装集合，`WorkflowMode=optional|default|disabled` 决定启用方式；二者与 S/M/H 风险、C1–C5 能力建议分别独立。
3. 未指定配置的新安装继续使用 Full，模式继续默认 optional；有效已有安装使用自身配置。升级、SetMode 或重装命令不得暗中切换配置。
4. 每个项目只由官方管理器管理一个配置，同一任务只有一个控制器。其他工具文件可以共存；文件存在本身不表示激活。
5. Full 的现有路径、角色锚点、七个 Skill 名称及宿主目标兼容。Lite 初版直接读取短规则，不部署这些 Full Skill；仅支持 SkillTarget=none，其他取值在写入前明确拒绝。
6. Full 的既有 EngRelay／ai-collaboration 名称等价关系不变。Lite 项目中的 EngRelay 或 EngRelay-Lite 进入 Lite；明确选择未安装配置或 Full 专属入口时说明不匹配，不自动切换或创建另一套运行态。
7. Lite 支持 S/M/H；高风险不能因 Lite 而降级。三类聚合职责不强制增加会话，但执行、审查及 H 所需验证仍须满足实际独立性。
8. 规则短不意味着取消交接落盘、证据、累计审查上限或安装归属保护。已授权的正常编辑、技术选择和本地 CLI／IDE 选择不新增请示。

## 第一期：协议与样例定稿

### 目标

把 Lite 的价值转成可验收协议，先解决来源材料中已经发现的冲突，再进入产品代码。该期以源码侧设计和虚构样例交付，不宣称 Lite 已可官方安装。

### 具体计划

- 记录输入版本、相关文件指纹、来源及版权说明，制作脱敏的行为比较表。不把私人目录、原始快照或私人绝对路径提交仓库。
- 定义精简读取路径：项目适用指令、Lite 短规则、项目配置、当前任务或队列条目；接手时增加当前交接及明确点名的证据。允许按需读取目标源码、模块指令和验收依据，避免“只能读四份文件”的封闭限制。
- 定义三类职责：负责人定范围与授权；执行者连续完成设计细节、实施和自查；评审者负责所需独立审查／验证。S 自查，M 独立审查并复核必须修项，H 按实际风险满足设计及独立验证要求。默认三次累计 verdict，有限追加授权沿用既有规则。
- 收紧闸门：只有超出授权、重大范围／验收／风险变化、真实权限缺失或明显超预期成本等才等待负责人；既有授权可覆盖的动作不重复确认。
- 定义短交接：任务身份、修订号、当前执行归属、动作、是否需要人类介入、累计审查次数、成果与证据、可执行下一指令。Agent 派发另带一行 C1–C5 建议，继续／关闭／人工决定省略该行。
- 定义写入、回读、预期状态核对及只读评审返回的发布责任；旧状态冲突不得按最大修订号或时间戳胜出。无法安全恢复时说明具体冲突，不建设通用恢复引擎。
- 定义队列授权、任务依赖、阻塞任务另存交接、逐项收口及归档。把“自动接力”限定为活跃 Agent 顺序处理，断线不等于后台自动唤醒。
- 完成新旧安装清单、配置投影、旧包拒绝新格式和项目配置归属的设计，并准备下述场景的输入与预期。存在不能执行的设计障碍时先修正。

### 验收与交付边界

设计须回答下列问题：状态谁写、只读返回谁发布、冲突如何处理、哪个任务可继续、审查如何累计、配置如何识别、旧管理器如何拒绝。样例至少覆盖正常接续、必须修复后复核、远期环境预告、依赖阻塞、旧交接冲突与授权耗尽。

必要独立设计审查完成后才能进入相应实现；不存在额外的“每期必须再找负责人批准”通用门槛。第一期不得把样例文本核对称为脚本行为或实际 Agent 遵从验证。

## 第二期：产品与共用管理器集成

### 目标

真正按所选配置安装和维护，避免把全部 Full 文档装入 Lite，或维护第二套简化但缺少保护的安装器。

### 具体计划

1. 在 `payload/docs/ai-collaboration/lite/` 编写规范 Lite 规则、配置／队列／任务／交接模板及小型只读校验器；Agent 契约与机器字段保持英文。完整档位表不在短交接中重复。
2. 扩展现有管理器的安装计划：Full 使用现有集合并排除 Lite 子树；Lite 仅把明确列出的 Lite 内容映射到 `docs/engrelay-lite/`，加必要管理块及忽略项。不复制私人 Lite 的 install.ps1。
3. 安装清单登记配置身份及精确投影。新格式提升 manifest 的 version；新管理器只把可信、已识别的 version=1 安装解释为 Full，并通过受保护升级转换。未知、移动、损坏及漂移清单继续拒绝，旧版本指纹不重新计算。
4. 旧管理器必须在目标写入前拒绝新清单；恢复说明保留对应管理器、可信包和原始备份，不承诺直接降级。新增投影不得削弱完整发行包的文件集合及 SHA256 检查。
5. 项目配置首次由模板创建，之后归属项目，升级及卸载保留；在新清单中显式表达，不能冒用旧 Adopt 的可信历史标记。运行态统一位于 `.ai/engrelay-lite/`，不与 Full 的 `.ai/current-task.md`、`.ai/handoff.md` 混写。
6. Install／Status／CheckVersion／Upgrade／SetMode／Uninstall 按配置工作；既有 Adopt 只保持已登记历史支持，不新增对私人 Lite 的自动接管。重复 Install 保持幂等；不同配置或 SkillTarget 请求在写入前拒绝。
7. 保持单一管理块和模式优先级，保护块外编辑。诊断报告配置、模式、文件归属、可读入口和不匹配项；保留 Full doctor 旧路径，只读诊断不等于宿主加载证明。
8. 用 PowerShell 5.1／7 的 GUID 临时目录检查两种配置的生命周期、漂移拒绝、用户文件／配置／运行态保留、旧 Full 升级、失败恢复及预览的零写入。检查实际支持 Preview 的路径，不借此增加全生命周期通用 Preview API。
9. 同步最小可用的双语安装、启用、接续与诊断指引，并登记新输入的来源和完整适用通知。README 和 CHANGELOG 先写未发布行为，不提前标版本已发行。

### 验收与交付边界

第二期结束应有可在隔离目录使用的候选实现。未指定配置的旧使用方式保持 Full；Lite 不安装 Full 角色链或七个 Skill；两种配置的升级／卸载均保护项目内容。

安装与清单转换批次属于高投入部分，按 H 影响保留必要设计审查、独立代码审查及独立验证。其余批次按实际影响处理，不展开两配置 × 全宿主 × 全模式的无差别测试矩阵。

## 第三期：使用演练与发行准备

### 目标

确认 Lite 在实际读取和操作上更轻，并且接续、独立审查和安装保护仍可解释、可复核。

### 具体计划

- 在虚构、可丢弃项目上完成 S 级直接收口、M 级审查／修复／复核、H 级独立验证、跨会话 continue、只读返回发布及多任务依赖／阻塞演练。
- 用相同任务与明确输入口径比较 Lite／Full 的必读上下文、人工复制或决定次数、非必要角色切换及交接正确性。有真实 Agent 运行时记录宿主和模型；不可用时报告缺口，不能用预填文本冒充行为证据。
- 汇总真实缺陷，按既有有限审查与修复规则处理。发现相同问题不得换阶段、换模型或重开记录清零。
- 完成双语 README、快速入门、选择指南、迁移／恢复说明、开发说明、CHANGELOG 及来源通知；人类文档严格分语种，Agent 契约与机器模板不重复维护中文版本。
- 完成独立审查及所需 H 验证；仅在输入或依赖变化时补跑相应检查，不为阶段收尾重复全部历史套件。
- 在明确候选提交确定后，按现有 git archive 流程导出干净暂存包，重建完整 snapshot 并检查集合与字节；固定旧包和未测边界。该步骤必须使用届时实际提交，不伪造当前工作区为干净候选。
- 输出发行准备结论和用户可复制的操作方式。真实项目安装、邀请外部试用、Git 提交／推送及 GitHub Release 不包含在准备结论中，按适用请求另行执行。

### 验收与交付边界

Lite 完成代表性任务所需的规定读取集合应小于 Full；同时不依赖隐藏的 Full 必读契约。报告实际文件／字节与上下文依据；有可靠 tokenizer 才报告 token。不从规则行数宣称性能提升或所有模型零遗漏。

三期整体完成须有：两种配置受保护生命周期证据、代表性行为证据、必要审查／验证、对应文档和完整候选包证据。缺少所需实际演练时保持“待验证”，不能仅以结构通过宣布完成。

## 后续候选项：不计入这三期

| 候选项 | 本轮处理 | 再评估条件 |
| --- | --- | --- |
| Full／Lite 未完成任务自动转换 | 不实施；保留原状态，提供人工核对与明确交接指引 | 有重复需求且身份、证据与计数转换规则可验证 |
| 私人 Lite 原位 Adopt | 不自动接管；由用户先保留输入，使用干净官方安装路径 | 有稳定、可识别且具备可信指纹的旧布局 |
| 单独 Lite ZIP 或独立版本线 | 维持一个完整包和统一版本 | 有实际分发成本证据 |
| 任意能力模块、全部宿主 Lite Skill | 固定两配置，Lite 先用显式规则读取 | 有具体宿主需求及加载验证条件 |
| 后台调度、自动唤醒、锁／心跳服务 | 不实施 | 作为独立产品需求重新评估 |
| Full 全面提示词重构或新增统计系统 | 保持原跟踪状态，不借整合扩大范围 | 有原事项的独立范围与试点依据 |

## 执行与成本控制

路线图不设日历工期或节省百分比。第二期成本最高，来自清单转换、配置投影与保护检查；较小替代是仅给 Full 增加轻量阅读入口，但它不能提供真正的 Lite 安装集合，因此本次仍采用选定方案。

相邻、非独立动作由同一负责 Agent 连续完成。只有选择角色流程时才创建对应运行态；既有已关闭批次和 Review 不复制、不重开。阶段划分不增加审查额度、不改变实际权限。高投入低收益的新扩展先说明收益、成本、较小方案及建议。
