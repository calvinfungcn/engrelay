# Proposal

## Why

现有交接可跨会话提供下一角色指令，但没有明确约束由用户选择平台还是当前 Agent 自动接手。用户无法可靠地按角色分配多个订阅额度，也可能误把已有业务实施授权当作自动启动其他 Agent 的授权。

## What Changes

- **BREAKING（新 Full 任务的行为默认值）**：默认由用户人工接力正式 Agent 派发。交接保存、回读和校验后，当前角色结束本轮；用户明确授权自动接续时，在原有权限和独立性范围内继续。
- 区分角色派发、同角色继续、实际负责人决定及环境阻塞；保留已在进行中的任务、明确选择和旧交接，不把人工转交伪装成新的审批。
- Lite 保留已批准就绪队列的默认顺序工作，支持用户明确选择人工接力，不引入 Full 专属入口。
- 在既有交接和回复中简短说明人工转交及下一角色能力建议；澄清现有 `Human Action Required` 枚举不能单独表达人工转交，保留旧消费者可能误读的限制。
- 说明共享工作区与非共享工具的最小接续路径、输入隐私和写回限制；同步受影响的中英文人类说明。

## Capabilities

### New Capabilities

无；复用既有 Full 和 Lite 交接与授权机制。

### Modified Capabilities

- `collaboration-package`：新增人工派发默认、显式自动接续覆盖、保留旧批次语义及真实转交提示。
- `workflow-profiles`：保留 Lite 默认队列，允许明确的人工接力约束，并保持既有结构与项目配置归属。

## Impact

影响规范 Skill、Full 角色和路由说明、Lite 短规则及相关人类指南；公开行为变化涉及双语 README 与 CHANGELOG。保留现有机器字段、枚举、安装路径、配置与审查独立性，不新增调度器、自动唤醒或模型排名。新版提示约束模型行为，不构成进程级强制；实际宿主遵循和 token 用量须以有界证据为准。
