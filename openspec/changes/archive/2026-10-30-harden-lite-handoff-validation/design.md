## Goals / Non-Goals

**Goals:**

- 同一可执行动作不因使用 continue 而绕过既有额度。
- 命令、章节及来源采用一致的围栏边界，避免从示例拼出权威。
- 有效旧记录继续可检查，错误记录得到具体诊断，所有检查保持只读。

**Non-Goals:**

- 完整 CommonMark 解析器、外部依赖、通用解析框架、新公开接口或持久化格式。
- 来源真实性认证、自动恢复发布、自动修改历史 handoff、批量迁移。
- 管理器 F3／F4、Full 校验器改造及额外宿主演练；后续入口见提案。

## Decisions

### 1. 以是否执行工作决定额度检查

复用 Test-Capacity，对已解析合法路由中的 executable continue 与 Agent dispatch 执行同一检查，使用 Evidence 的真实围栏外授权。默认计数小于 3 才有剩余额度；超额动作只能由既有字段完整、任务及证据匹配、from <= N < through 的有限扩展支持。不新增额度参数或 Routing 字段，也不由字段结构认证真实负责人授权。

负责人等待与合法关闭不消费新的执行额度。真实 blocked 记录也不执行修复，可在额度耗尽时保留原恢复条件和人类摘要，不强迫 Agent 为了记录工具故障伪造新的负责人决定。障碍解决后，任何可执行 continue／dispatch 必须重检额度；没有剩余授权时走既有负责人出口。不得把 blocked 当作新修复循环的跳板。

较小替代方案只补文案，无法拦住已复现的错误；对所有 continue 一律阻断又会误拒现有等待，因此只约束可执行动作。

### 2. 复用文件内围栏遍历，保留真实位置

在 validate-state.ps1 内复用或小幅提取既有识别：开启围栏为 0–3 个前导空格后至少三个相同反引号或波浪线；结束须同字符、长度不少于开启长度且无非空尾随。较短或异类内部围栏仍是块内容，未闭合报错。

章节、来源及命令消费同一识别结果，按需取得围栏外行、实际块内容及原始位置；不强制特定辅助函数名称或数据结构。位置只在本次读取内使用，不增加日志台账、运行态字段或另一套内容缓存。保留现有章节返回含义，避免扩大为格式重写。

来源元数据可在文件顶部或其他真实围栏外位置出现，不以是否隶属某个二级标题为新增前提。显式指定的唯一来源内，外部真实重复字段仍失败；所有围栏中的字段都不参与匹配。Named result、旧 SHA256、修订相邻、实际计数、风险及来源职责／归属等既有检查继续执行，不能由新文本提取替代。

### 3. 只检查实际可复制的动作命令

Agent dispatch 使用真实 Operator Command 小节；continue 使用 Current Status 内真实、唯一的 Continuation Command 三级小节，其范围止于下一同级或更高标题。围栏中的同名标题不选取命令，不能继续用原始文本第一次 IndexOf 定位。

每个动作要求该范围内唯一实际 text 命令块，完整且闭合；保留现有三反引号 text，统一识别后也接受合法较长反引号／波浪线 text。任务与职责及 Read、Objective、Constraints、Output、Follow 的非空内容必须同处该块。其他小节、围栏外叙述或其他块不能补齐；多个实际 text 命令块明确报歧义。身份匹配应避免用另一个较长任务标识包含本任务标识而误通过，不新增命令字段。

此要求使用户复制的块真正自包含。它不规定字段正文长度、具体措辞或额外模型能力证明，也不把非阻断的 C1–C5 建议升级为条件。

### 4. 文档与兼容边界

Lite RULES.md 明确可执行额度、非执行等待及命令／来源的真实围栏边界；模板仅在现有文本不清楚时作最小调整，不加字段。两份 Lite README 去除过时候选状态，准确说明 1.10.0 已提供 Lite；保留 v1.9.6 管理器拒绝 v2、配置保留及无自动唤醒等仍成立的限制。

根 README 双语仅补相关校验说明，CHANGELOG 双语只记 Unreleased 修复，不选择新版本或宣称已发行。人类文档双语对应，Agent 契约继续英文。源码导航保留本活动变更与后续 F3／F4 的已确认待实施状态，不建立第二任务清单。

lite-1 身份、11 个 Routing 字段、参数、路径和合法既有格式不变。旧实现误放行的不完整命令、围栏内假来源或超额可执行状态可能新近失败；报告具体原因，由有权 Agent 在原更新边界修正，不自动改写文件或将旧记录追溯改为未完成。

### 5. 一个可交付批次，适用一次聚合代码审查

本批保持 engrelay-lite-validation-hardening-20261029-01、M，修复与文档组成一个可观测结果；预计一至两个实施会话。没有新架构、复杂度例外或仅内部基础步骤的验收，故不强制增加单独 Design Review，下一角色为 Implementation Engineer。

本次设计编写、OpenSpec 结构检查不是 verdict，累计仍 0/3。代码完成后取得一次独立 M 代码审查，修复必须项后取得对应独立确认；审查／复核及其他正式 verdict 单调累计，旧历史不回填、不重置。达到上限且未完成时使用既有有限授权出口，不能再自行开展一轮。

本节保留首轮规划及批次身份。关闭后追加审计与负责人明确授权的关联纠错见决定 7；当前累计已为 2/3，不能沿用上段的历史 0/3。

### 6. 先反例，后局部修复及对照

扩展既有 test-lite-state.ps1 的具名虚构输入；先保存受影响反例在旧代码中的失败断言，再实现修复，覆盖完整命令与来源的有效对照。最终只运行更新后的 Lite 状态套件，在两种 Windows PowerShell 宿主记录真实参数、退出码、诊断、测试脚本／校验器哈希及零写入。该入口本身的既有 39 例属于相关行为回归，不扩展到所有安装矩阵或 Full 262 例。

| 验证组 | 必需观察 |
| --- | --- |
| 额度 | 2、3、8；可执行 continue 和 dispatch；有效、用尽、错任务／无效扩展；负责人等待、close、blocked 及恢复执行重检 |
| 命令 | 合法旧块、较长／波浪线块；块外及其他小节补标签失败；多 text 块、缺身份／内容、伪标题、伪结束、未闭合 |
| 来源 | 围栏内字段不能补齐；合法外部元数据加完整嵌套响应通过；外部重复失败；既有哈希、归属、计数冲突继续失败 |
| 保留行为 | 五项显式预期、合法路由及 C 档缺失仅提醒；成功和失败均不改输入 |
| 文档 | 四份 README 和两份 CHANGELOG 的实质说明、引用与未发行状态；无机械文字匹配测试 |

不需要先执行大规模新 Agent 演练来证明文本解析和分支判断，也不把字节数换算为 token 收益。没有代码或产品规则变动时不重跑这些运行检查。

### 7. 关闭后追加审计的集中纠错

round 01 的 PASS、原 5/5 和 revision 5 accepted close 是保留的历史结论；round 02 的追加审计确认 CR-01／CR-02／CR-03，当前不能据旧关闭归档。负责人于 2026-10-30 明确要求 Chief Designer 安排集中纠错。本次不从审计文件恢复关闭态，不重放旧派发：原 current-task／handoff 原样留存后，在同一变更内建立关联纠错批次 engrelay-lite-validation-correction-20261030-01，继承同一未完验收的累计 2/3；批次名变化不产生新额度。原审查索引是两批共享的计数依据。

最小方案只修既有命令提取和身份比较，不增加产品要求：

| 发现 | 修复边界与必需对照 |
| --- | --- |
| CR-01 | 身份边界覆盖当前允许的全部 ID 字符；T01 不得匹配 T01.-other、T01._other、T01..other。保留句末 T01. 及合法点号 ID 的完整身份，不通过限制 Routing 合法字符规避问题。 |
| CR-02 | 围栏外真实 H1 结束原 H2 的归属，空 Operator Command 不借用下一 H1 的指令；保留真实命令、合法 H3 内容和围栏内伪标题。 |
| CR-03 | text 信息字符串按序数不区分大小写识别，保留 TEXT／Text 的既有接受行为；身份、闭合、唯一块和五项内容仍必须成立，大小写变体不形成多块漏洞。 |

先在现有 test-lite-state.ps1 中补实际子进程反例并记录修复前失败，再局部修复。dispatch／continue 共用逻辑的受影响路径和有效对照均须检查。最后在 5.1／7 运行更新后的 Lite 状态套件，保留退出、诊断、输入哈希和零写入；不重跑安装矩阵或 Full 全套。两宿主各 72 例的旧通过记录只适用于旧输入，不能替代本次新证据。

唯一 tasks.md 将 2.2、4.1、4.2、4.3 恢复为未完成，保留首轮完成的历史说明；1.1、2.1、3.1 不因本次纠错被重做。修复工程师不能将独立审查／关闭提前勾选，发现最多记 fixed-not-verified。代码完成后交原追加审计的独立 Code Reviewer 作一次聚合确认，发出 verdict 时累计 2→3；Chief Designer 本次规划和工程自测不计 verdict。第 3 轮仍未通过时返回负责人决定，不另启一轮或用新批次清零。

本方案不增加依赖、字段、运行时引擎或模型选择流程，也不扩大到 F3／F4。主要副作用是身份边界过严误拒句末标点、H1 截断误伤围栏内标题，以及大小写放宽时漏报歧义；上述有效／失败对照直接约束这些风险。原非阻断 EOF 空行可随受影响文案整理，但不因此单开修复或审查。归档及 Git 操作仍以纠错后独立审查通过为前提；不授权 Release、真实安装或全局修改。

## Risks / Trade-offs

- 拒绝旧错误格式导致已有流程需要修正 → 明确诊断、不自动回填、保留有效旧模板和非阻断建议。
- 提取遍历逻辑改变章节识别 → 用 Raw／Plain、嵌套围栏、真实小节定位和全部现有 Lite 用例核对，不复制 Full 大型实现。
- blocked 记录被误读为新增授权 → 规则和反例明确恢复执行重检，状态记录不构成执行许可。
- 测试和文档反复增加成本 → 只增缺失分支和有效对照，使用已有入口，无新框架、字段、统计或普遍人工确认。
- 带真实私有路径的反例进入公开源码 → 测试使用虚构任务和临时根；公开规划只保留行为及相对源码位置，原始日志留本地。

## Migration Plan

修复经独立审查后再由另行授权的发行流程选择版本、干净导出、生成匹配清单并核对包。当前根 snapshot 保留上次发行元数据，不用开发目录重建。

正常项目后续沿用官方 Upgrade；本批不新增安装文件或改变投影。旧交接读取失败时由获准写者在对应任务边界修正并重新检查，保留原证据，不执行自动迁移。确需回退时使用对应可信完整包和现有受保护恢复流程，不手改安装清单。

## Open Questions

无阻止本批实施的未决设计问题。F3／F4 的管理器技术方案与后续发行版本由各自后续任务核定，不是本批验收前置。
