# Design

## Context

动机与范围见 [proposal](proposal.md)，可观察行为见两份 delta。当前 Full `continue` 要求报告关闭结果但未规定面向用户的具体下一步；`start` 将活动 change 与未关闭 batch 并列转交 `continue`，而批次规范允许同一 change 的后续工作经新 Task Intake。`agent-rules.md` 的未定位手册读取与已存在的按需章节规则不够一致。Lite 已在自身规则中顺序选择已批准且满足依赖的任务，无 Full Skill。

官方管理器的 `Get-BasePlan` 将 Full 的 `agent-rules.md` 插入目标 AGENTS 受管块；`Get-UpgradePlan` 依旧记录及 `Get-ManagedReplacement` 保护管理块外内容。故该文案更改需要有界旧包升级核对，但不需要新安装集合或管理器分支。图索引对管理器有局部解析缺口；上述函数已按源码确认，不能将函数阅读当作实际升级结果。

## Goals / Non-Goals

**Goals:** 让关闭状态有简短、真实且有用的答复；对明确授权的后续请求使用已有分流；减少无关规则的默认读取，同时保持历史与安全边界。

**Non-Goals:** 不新增编排引擎、状态字段、计费工具、常驻进程、自动配置切换或独立任务清单；不重新打开旧关闭、不改变独立审查门槛、不宣称全宿主遵从或固定 token 节省。

## Decisions

### 1. 按状态和请求分支，不重新执行已关闭批次

先核对 WorkflowMode、所选控制器、最新任务／交接、明确命名的权威证据及适用恢复候选；有冲突先走已有恢复／解释出口。真实 `close` 的回复区分 ordinary accepted、owner-limited accepted、stopped 和 superseded，说明本批实际结果、已知未完成或未知、没有下一角色，以及一条适用的用户下一步。只需状态答复时保持现有文件，不为了生成提示写新交接。

父提案仍有未完成项而用户仅说“继续”时，依据唯一 tasks.md 说明已知范围并提供最小可复制请求；任务或权限不明确不自动选择。用户在本次请求中明确指定并授权可区分的后续工作，且没有真实等待、权限冲突或同批写入冲突时，保留旧关闭和历史，在同一会话调用现有 Task Intake 工作流处理适用后续范围；这不是隐式调用只允许显式选择的 `ai-collab-start` Skill，也不是自动执行旧 Operator Command。用户当前明确请求本身可以是适用授权。后续为同一未完成验收时保持原累计 verdict 和适用有限额度；真正不同的范围单独识别其计数，不改写历史。目标不明或只是延迟的旧消息不视为新工作。

负责人明确要求关闭后追加一次独立审查时，沿用现有一次授权、原历史和有限额度规则；实施者不能自审，一次审查不自动授权修复循环。外部操作继续受具体授权与现有入口约束。

### 2. 消除 start 与 continue 的闭环

`start` 在当前批次仍可执行、等待或有待恢复转移时按现有规则接续同一工作；当前批次已关闭但父 change 的另一范围被明确授权时，使用 Task Intake 选择实际 checklist 项、保护原关闭并确定新批次，而不是只因父 change 仍活动就转发到已关闭的 `continue`。同一未完成验收不因为新批次而重获额度。若任务缺少状态或范围，给出最小恢复或选择方向。

替代方案是要求用户记住何时换 Skill；该方案无需改路由，但不能满足明确后续请求无需重复发送的已确认体验。

### 3. 先判动作，再读取触发的规则

`continue` 的常规入口先读适用项目指令、实时 current-task 与 handoff，并按需核实具名权威。规则章节分别在适用时读取：可执行接续、Agent／人类派发、待恢复来源、实际写入边界及额度判断；不能提前省略这些触发条件。新 Agent、上下文缺失、输入变化或规则疑问时刷新相关权威；同会话仅复用已读且已知未变的参考。项目或已触发 Skill 的必读要求优先，不新增强制禁读、缓存凭证或台账。

`agent-rules.md` 改为指定实际角色和交接需要的适用章节，与公共预检对齐；继续要求角色职责及真实交接校验。既有短命令骨架保留 Role/Batch、Read、Objective、Constraints、Output、Follow 六项，修正文案数字。可选的设计或学习材料仍按原触发条件读取；不复制第二份速查手册。

### 4. Lite 保持自己的队列和入口

Lite 沿用 `RULES.md`、项目配置和 `.ai/engrelay-lite/`。当前任务完成后，已批准、依赖满足且无冲突的下一项继续按原有规则执行；没有可执行项时说明实际完成、待批准／依赖或未知状态，并给出 Lite 可用的下一步，不建议 Full 专属 Skill、不切换配置。仅在 Lite 自身短规则及现有双语说明增加少量内容，不新增 Full 依赖或改变队列格式。

### 5. 范围与验收

一个 M 级相干批次覆盖关闭提示、两入口分流及其读取约束。唯一清单为本变更 `tasks.md`；实现和已有独立代码审查分别由符合独立性的角色执行。Design Reviewer：**no**。本方案不新增接口、结构、依赖或额外授权类型，首个用户可见结果可用明确状态与请求检验；正常 M 独立审查覆盖完整影响。若实施需要改变机器协议、权限模型或新增架构，再回首席设计师评估。

最小检查覆盖：普通关闭与父范围完成、父范围未完成但请求模糊、明确授权的后续项、重复旧消息、有限接受／stopped、状态缺失冲突、原审查额度、真实等待、disabled／另一控制器、Lite 可执行和不可执行队列，以及新会话／同会话刷新。以具名虚构输入和实际来源核对产品指引，不将示例、静态扫描或结构检查冒充宿主 Agent 行为。可用且成本相称时做一次真实 Agent 小样本并保存输入及输出；不可取得则明确该行为未验证。用量对比为可选且分别记录模型、宿主、缓存和未知值。

修改受管 Full 入口时，以对应可信旧包和隔离候选包做至少一次受影响的 Full 升级检查，核对受管块内更新、块外项目内容和既有模式／目标保持；有漂移时沿用原拒绝。无匹配旧包时保持升级行为未验证，不伪造通过。只在实际输入受影响时扩展到其他宿主或配置，不重跑所有历史套件。

## Risks / Trade-offs

- 新请求误认成旧消息或反之 → 以本次明确目标、适用授权和唯一任务权威区分；不明确时返回具体建议，不根据历史聊天自行补全。
- 旧关闭后执行绕过额度或独立性 → 同一验收保留历史计数和有限授权；关闭后审查、真实新缺陷和新范围分别走现有路径。
- 缩短阅读遗漏必要规则 → 保留项目／Skill 必读、状态刷新和按分支加载；必要时可多读，不引入禁止阅读。
- 公开说明或 Lite 入口失配 → 中英文成对核对，Lite 不引用 Full Skill；不修改生成的宿主副本。
- 受管入口变更影响升级 → 使用有来源的隔离 Full 升级检查；不会把只读检查称为升级已通过。
- 增加示例和分支抵消上下文收益 → 原地精简并按需引用，不强制全任务采集 token；仅在实际有数据时报告局部测量。

## Migration Plan

旧状态、历史 Review 和旧安装不迁移。用户未来使用官方受保护 Upgrade 时由现有管理器替换未漂移的受管内容；不覆盖项目自有内容或改变配置。开发期间保留既有根 `snapshot.json`；后续若另获发行授权，在干净暂存中重建匹配清单。回退使用对应可信旧包及既有受保护流程。
