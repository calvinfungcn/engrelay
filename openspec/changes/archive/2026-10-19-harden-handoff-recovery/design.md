# Design

## Context

动机和范围见 [proposal.md](proposal.md)；行为要求见 [增量规范](specs/collaboration-package/spec.md)。本设计以当前 v1.9.3 源码为依据，不把旧批次验收当作本次新语义的证明。

| 核对位置 | 现有能力和设计依据 |
| --- | --- |
| `payload/docs/ai-collaboration/handoff-schema.md` General Rules、Source-matched recovery | 已有指纹、修订号、pending/applied/advanced/conflict、写前重读、额度和独立性保护；Candidate 条件主要依赖 review index。 |
| 同文件 Autonomous Continuation | 可执行 continue 的命令位于 Current Status；现有 applied 条件却只比较 Routing 和 Operator Command，存在比较面缺口。 |
| `templates/implementation-result.template.md` Next Action | 只有 Decision、Reason 和 Action State 指针，适合承载有需要的完整恢复副本，不能把普通结果直接当路由。 |
| `skills/ai-collab-continue/SKILL.md` Procedure | 发现已完成替代交接的入口仍以 review-linked 记录表述，需要同步来源范围。 |
| `agent-prompts.md` Common Preflight、workflows 边界规则 | 已要求边界写回与主 Agent 发布；本批细化同角色会话切换及先保存完整结果再摘要的时序。 |
| `agent-rules.md` Runtime and exit rules | real legacy execution 与当前按任务选择的语义混淆。 |
| `scripts/manage.ps1` Get-ManagedInsertion、Get-ManagedReplacement | 前者生成 Legacy 标题；后者以清单记录的精确 insertion 找到旧块，仅拼接替换块内内容并保留外部字节。标题文案可改，不需要改保护算法。 |
| `scripts/validate-runtime-state.ps1` | 五个 Expected 参数已校验非法值并比较明确预期；默认只检查结构。本批不把它扩展成恢复选择器或时间戳判断器。 |

代码定位先使用知识图谱，再读取实际源码。图谱报告 validator 存在部分解析覆盖，不能用图谱缺项推断没有实现。无自动恢复执行器；下述算法是负责 Agent 应遵守的协议，演练只能验证所演练的文件操作和规则，不能证明所有宿主遵从。

## Goals / Non-Goals

**Goals:**

- 使明确关联且完整的实现交接获得与审查交接相同的安全恢复路径。
- 在相同 revision 时正确区分“已应用”和“执行内容冲突”。
- 缩小可预见会话切换及子代理摘要前的丢失窗口，保持摘要短、正常微步骤成本低。

**Non-Goals:**

- 不让普通结果、mtime、文件编号或候选自我声明取得状态权威。
- 不添加新角色、机器字段、公共参数、恢复命令、队列、事务日志、锁或宿主钩子。
- 不强制所有结果都复制完整交接，不为纯文案或每个微步骤建立结果文件。
- 不修改真实项目、不接管项目块外内容、不提供突然断线零丢失或原子发布保证。

## Decisions

### 1. Minimal Option 与可行性

选择“既有产物内的按需完整恢复交接 + 有界来源读取 + 按动作比较 + 明确边界时序”。只改文案的泛化禁令无法解决来源发现和比较面的具体缺口；自动钩子、WAL、写入服务则会新增状态权威、平台权限和故障恢复成本，当前没有相称收益。

可行性结论：proceed，先作独立设计审查。现有完整 handoff 结构、外层围栏、文件哈希、revision、expected-state 和可丢弃目录足够支撑本方案。预期一至两个实施会话，不新增依赖或后台进程。权限拒绝和突发中断仍保留诚实 fallback，不通过更严措辞承诺技术强制。

首个可见结果：虚构批次在旧 live 中明确点名一个结果文件；文件保存已完成工作的完整下一交接。按协议核对后发布，再次接续不重放；将同 revision 的 continue 目标改成另一步时，必须保留 live 并报告 conflict。

### 2. 发现来源：具体引用，不扫描目录

只从恢复前已经存在的权威输入取得候选位置：

- 正式审查继续使用本任务明确关联的审查索引所点名的当前记录，不遍历历史轮次寻找“最大号”。
- 实现/修复结果使用 `.ai/current-task.md` 的具体文件引用，或旧 live handoff 的 Next input files、Next output files、Authoritative Evidence 中的具体结果路径。计划产生该结果时，先在正常任务/派发输出中点名；通配符 `.ai/round-XX-result.md`、随口称“最新结果”或候选内部自我引用都不构成关联。
- 同路径的重复引用只读取一次；不沿候选内部链接递归寻找新权威，也不因为结果不在 review index 而伪造审查记录。

被引用的普通结果没有完整容器时，不升级为恢复候选。若明确声称交付恢复容器却缺少内容或依据，报告缺失而不是从摘要补齐。完全未被点名的文件不自动读取或恢复；用户明确带来的 response/subagent 交接仍按原适用性及来源保护核对。

先沿用现有 closed、真实等待、有限授权和独立性保护。对已关联容器使用已有指纹/revision 判定：已 applied 或 advanced 的历史来源不再派发；只有 pending 可以发布。同一输入出现两个不同的 pending 转移，或出现未能解释的来源/归属冲突，停止覆盖并指出两者，不按编号、时间或投票选取。重复引用同一来源不制造假冲突；此细化不是允许自行合并两个状态。

### 3. 容器：按需一份完整文件形交接

在现有 implementation-result 的 Next Action 内，以足够长的外层围栏保存一份可提取、可交给现有 validator 的完整文件形 handoff，包含真实 `## Routing` 和适用的状态、证据、风险、状态影响及命令段。不要只保存一个 Operator Command 或三个路由字段。来源叙述放在围栏旁，沿用批次、来源角色/Agent、工作生产者、verdict 或 none、实际累计 Review round、旧字节 SHA256、旧 revision 和目标 revision；不增加 Routing 机器字段。

新实现恢复容器需要真实旧 SHA256，不能省略后自动落入旧无指纹宽松分支。若旧文件已有 revision，目标为下一值；若旧文件无 revision，叙述明确记录其缺失，新候选从 1 开始，不回填原文件或伪造历史。旧审查/响应交接仍保留既有兼容分支；本次不扩大其无指纹适用面。

使用范围限于：已有结果确需承载受限交接，或已知会话边界需要保存可恢复的完整转移。不把所有普通结果改成完整 handoff 副本。需要该容器时，先保存并读回完整候选，再发布 live；这只能保护“完整候选已保存而 live 尚未发布”的窗口。未写出任何完整候选的突发中断仍不可凭空恢复。角色有权限发布时仍应当轮完成发布，不能把容器当作延迟写回的借口。

容器只保存已完成事实及已决定下一步，不伪造运行过的检查。live handoff 只链接结果，不重复检查日志或发现表；一次转移只保留一个完整容器，重试不追加相同副本。未落盘说明放在候选外的来源叙述，发布回执放在既有外置检查容器；不要为“写回成功”循环修改被检 Current Status。复制实际审查结论不产生新 verdict；实现完成本身不增加 Review round。

### 4. applied 比较覆盖真实执行内容

保持现有判定优先级：先处理保护，再识别旧指纹/旧 revision 完全匹配的 pending，之后判断 advanced 或同目标 revision 的 applied/conflict。不能因三个路由字段相同提前视为 applied。

同目标 revision 时，先比较完整 Routing，再按动作比较：

| 动作 | 还需比较的内容 | 不一致的结果 |
| --- | --- | --- |
| Agent dispatch | 完整 Operator Command，沿用原规则 | conflict，保留 live |
| 可执行 continue | 完整 Current Status，包括其叙述和嵌套 Continuation Command 的全部内容 | conflict，保留 live |
| 真实等待、human dispatch 或 close | 保留原等待、决定、关闭和最终证据保护，不新增快速应用出口 | 不以命令缺失推断已应用或自行解除限制 |

仅把 CRLF/LF 规范化为同一行尾，不作语义相似度、排序、删除围栏、忽略文字或仅比较“命令块存在”的处理。段落提取须保留嵌套命令围栏，不把围栏中的标题识别成顶层段落。旧 continue 没有命令块但状态叙述足够时，仍比较完整 Current Status；缺少新命令块不要求历史回填。相同 revision 下一个有命令块、另一个没有，不能凭相同路由放行。

这样不会修改原指纹算法或 validator；恢复后的来源归属不改成恢复者。写前重读，写后回读候选，再用来自候选决定的批次、动作、下一角色、实际 Review round 和目标 revision 执行现有预期校验。校验只证明声明值与文件相符，不认证来源或自动选路。

### 5. 边界、子代理与长检查

将“微步骤例外”明确限制为同一活跃负责会话里的相邻局部动作。计划结束会话、让出执行、切换负责会话或对外交接时，即使角色不变也先保存有效 handoff；保持原 continue 职责和真实计数，不把结束单次 runner 当作 blocked。

主 Agent 得到只读子代理的完整结论后，先核对同批来源和生产者归属，在原有获准结果或正式审查产物中保存完整发现及交接，再发布 live、回读及预期校验，然后才能仅向用户给摘要或派发下游。复用一个已适用容器，索引与 handoff 只链接；不为此默认为纯文案创建 implementation-result。没有任何写权限时保留完整响应交接，不能规避沙箱或无限重试。

可预见的长检查只有在已有实质进度且跨会话预算有现实风险时，才先保存简短 continue 恢复点并让日志写到外置位置；该状态说明检查尚未完成及如何检查实际进程/输出。替班会话先核对执行归属，不能因旧检查未返回而启动重复写入者。不得把所有测试都变成前后双重写回；突然强制终止之前没有写出的进度仍无保证。

### 6. 入口说明与项目侧后续

`agent-rules.md` 使用“当前已选择工作流的真实执行”表述；`scripts/manage.ps1` 仅将生成标题改为不暗示退役的工作流策略名称。兼容名称 ai-collaboration、managed begin/end、WorkflowMode、版本字段和清单 insertion 保护保持。源码检索只发现管理器生成处依赖该精确旧标题；仍由独立代码审查核对最终差异是否超出文案。

采用说明补充：读取项目现有入口，发现历史退役声明与当前选择冲突时，在该项目内协调适用性，不让安装升级自动删改用户块外内容。人类文档英文/中文对应；Agent 契约保持英文，不复制新的双语协议。

**LOCAL-ENTRY-01**：状态 deferred（已确认、待独立项目执行），归属为目标项目维护负责人 / Task Intake。证据类别是项目自有退役说明与现行管理块的适用性冲突；本提案只记录通用问题，具体目标和观察保存在本地接案证据，不进入公开工件。该项目下一负责 Agent 应独立核对入口，在既有授权及其文件系统权限下修正块外历史描述；不得手改受管块绕过归属，也不得要求卸载、真实升级或部署来完成文案修正。本批结束时明确该项仍未执行，不将产品完成冒充项目问题解决。它不阻塞本产品批次验收。

### 7. 验证与审查安排

唯一实施清单为 [tasks.md](tasks.md)。保持协议实现与证据范围相符：本批产品主要是 Agent 规则，不以关键词匹配或演练脚本自己返回 PASS 证明真实宿主行为。

用虚构批次和 GUID 可丢弃目录实际记录以下文件链路：

| 检查范围 | 必须观察到的结果 |
| --- | --- |
| 被旧输入点名的实现结果、无 review index | 完整容器匹配后写回、回读、预期校验；再次接续不重放，Review round 保持 |
| 只留普通总结、未知路径、自我引用、缺指纹 | 不推断恢复；指出必要来源缺失，不把正常旧结果认作无效安装 |
| 同 revision 的 continue | 相同内容识别已应用；不同状态说明/命令、有无块差异均 conflict；旧纯叙述、CRLF/LF、围栏内标题明确覆盖 |
| 冲突保护 | 跨批、不同 pending 来源、更新状态、写前改字节、close、真实等待、耗尽额度与有效/无效有限授权保持原出口 |
| 只读子代理与计划换会话 | 完整结论先保存、同轮发布、回读校验；无可写者仅完整响应；同角色会话边界更新，微步骤不额外写回 |
| 检查点和时间 | 检查未结束时不写成功；结果在验证后追加日志不因 mtime 较新而触发恢复 |

演练 helper 放在本批忽略证据目录，不作为新的部署恢复工具。修改前先记录来源/比较缺口的反例解释，修改后用实际文件操作证明目标链路，正式审查独立检查其与规范的对应；不在产品中建设第二套恢复引擎来“测试自己”。

主要演练使用 PowerShell 7；若复用或增加需兼容两宿主的 PowerShell helper，则对那些实际分支在 5.1 和 7 分别检查。validator 源码不变且哈希匹配时复用其匹配范围内证据，只对新 handoff 用预期值检查；若实施发现必须修改它，先记录范围影响并按实际变化运行双宿主定向/必要回归。管理器只改生成标题时，核对真实替换函数仍只拼接管理块、语法无误且输出逻辑无变；不为一句标题重放完整安装生命周期。若实际逻辑或兼容目录改变，才增加相应可丢弃夹具检查。

Design Review Decision：yes。恢复权威从 review-linked 扩展到明确点名的实现结果，且同 revision 的命令比较改变下游执行决策，这是必要且有界的公共/归属契约变化，需要一次独立设计审查，重点检查候选可发现性、比较等价性、旧记录兼容、复制成本和权限出口。实施后保留一次独立 M 代码/协议审查；所有 verdict 累计在本批，设计作者不自审，不能借旧批次或换角色重置额度。

## Risks / Trade-offs

- [完整容器增加字节与 token] → 只在既有结果确需恢复时保存一份，正常 handoff 链接结果，微步骤与普通结果不强制复制。
- [扩大候选面造成错误覆盖] → 预先具体关联、完整容器、真实指纹、原保护及写前重读；不扫描，不提升自我声明，不凭普通结果猜路由。
- [比较完整 Current Status 对编辑较保守] → 除行尾外的变更都明确报告 conflict，避免把命令改动当作展示差异；不静默覆盖，后续负责人根据证据协调。
- [Agent 忘记任何持久化或突然崩溃] → 限定检查点和先保存原始结果以缩小窗口，如实披露仍有未覆盖场景，不承诺技术强制。
- [管理块外仍有矛盾或多宿主未读规则] → 项目侧单独协调并保持待办归属，不增加默认激活或自动写入多宿主入口。
- [测试变成协议引擎或审查反复] → 只做聚焦文件演练，区分规则/脚本/真实宿主证据；一次聚合审查，按实际有限额度处理真实发现。

## Migration Plan

先完成独立设计审查，再只维护 canonical 源及必要双语公开说明。旧普通结果不批量迁移；缺少新容器不触发自动恢复，也不构成安装错误。新的按需容器在当次真实更新中携带明确来源，不回填旧归档。

本开发批次不安装到自身、不更新根发行 snapshot、不提交或发布。后续用户授权发行时再按干净 staging 流程记录实际新包字节；受管标题经官方管理动作更新，旧 insertion 和块外内容保护不变。若需要撤回本次未发布改动，按最终差异恢复规则/文案并检查受影响路径；不回滚真实项目状态，不改写既往证据。
