# Proposal

## Why

交接规范虽已有边界写回与只读响应 fallback，但实际生成的审查指令可能禁止 `.ai/` 写入，导致审查已完成而 live handoff 仍指向旧审查；接续入口缺少明确的恢复顺序。现有校验器只证明文件结构有效，无法判断旧文件是否符合本次已完成交接，需要补齐权限、持久化确认和接续闭环。

## What Changes

- 正式角色交接明确区分业务代码只读与交接产物可写；派发者不得仅因审查独立或泛称只读，自行增加无适用来源的 `.ai/` 禁写限制。用户或上位指令的明确禁令、实际工具权限限制继续生效。
- 真实派发、等待、计划会话中断和关闭边界先写 handoff，再回读核对及校验；回复简短报告实际持久化结果，连续微步骤不增加写回。
- 只准写审查产物时，把完整替代交接及来源匹配依据保存在现有审查记录中，索引仅链接；完全只读时在回复中保留同等信息并如实说明限制。
- 只读子代理返回后，仍活跃且获准写交接的主 Agent 须在本次交接结束前完成核对、落盘及回读；没有可写负责者时才保留未持久化交接，不把写回责任推给用户。
- 接续优先核对明确关联的同批次替代交接，由获准写入的 Agent 先持久化有效路由，再按原角色、授权、审查计数及独立性继续；防止重放旧派发或覆盖已前进状态。
- 为运行态校验器增加可选的预期批次、动作、下一角色、累计审查计数和修订号比对。参数可选保留旧调用兼容；采用新版契约且接口已可用的真实边界必须传入本次已决定的预期值，不以无参数结构通过代替该义务。
- 同步 canonical 契约、模板、接续 Skill、必要的双语公开说明和聚焦用例。

实施前修订已获用户明确确认：增加上述约束和原缺陷的完整恢复演练，保留同一变更、九项任务及已完成的首轮独立设计审查。原审查记录只证明其当时版本；本次细化不产生新 verdict，最终代码审查须覆盖修订内容。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `collaboration-package`：补充真实边界持久化、严格只读替代交接的安全恢复，以及兼容的可选预期状态检查。

## Impact

维护风险为 M。影响 `payload/docs/ai-collaboration/` 的 schema、角色提示、workflows、三种运行态模板、canonical 入口 Skill、validator 及其测试，必要时同步 `agent-rules.md`；两版项目 README、操作者说明和 CHANGELOG 只增加相关行为及限制的对应说明。复用现有文件、动作与证据容器，无新依赖、后台进程或状态数据库。新增可选 CLI 契约及恢复时的写入归属需一次独立设计审查，实施后保留独立 M 代码审查，累计 verdict 不重置。只使用虚构可丢弃夹具，不导入真实业务项目资料，不迁移历史、不承诺意外断线自动恢复，不发布或部署。发行清单在后续获授权发布时按干净 staging 流程处理。
