# Design

## Context

动机见 [proposal.md](proposal.md)。本轮源码基线为 `a4aff94d3970e5659c121874eba3817a561ad8ca`、v1.10.1；首次体验的旧两次试跑使用 v1.8.0，不代替新版演练。

| 已核对输入 | 当前事实与设计约束 |
| --- | --- |
| 根 README 两种语言、docs/quickstart 两种语言 | 已有安装、Git 基线、规范读取和 A/B 说明；Quickstart 仍要求自备任务并声明没有样例 |
| 已归档 improve-phase0-first-trial 的 proposal／tasks | 只交付选定八项改进；没有交付完整 Phase 0、公开样例或 G0 |
| payload 中 start／continue、Implementation Engineer 契约 | start 不实施；新会话依据当前文件接手，S 可自检关闭，M 维护交付需要独立审查 |
| scripts/manage.ps1 的 Get-BasePlan／Get-Plan／Get-InstalledLayout | Full 从 payload 的受支持路径构建安装集合；包根指南与源码样例不是部署路径；v2 布局变化另有 F4 后续 |
| .gitattributes、开发指南 | 安装导出排除 openspec 与 docs/reviews，完整包必须有匹配清单；源码检出不能直接作为安装源 |
| OpenSpec 双语导航 | Lite／Full、能力引导等已完成；样例待决定、G0 待验证、F3／F4 已确认待独立实施 |

图谱对 PowerShell 标记为部分覆盖；本轮核对了上述实际管理函数和脚本参数，不将图谱计数当作完整性证明。没有根 docs/ai-collaboration 安装副本，也不为设计向本仓库安装。

## Goals / Non-Goals

**Goals:**

- 用同一个固定任务闭合“取得样例与包 → A 交接 → 全新 B 修复并检查”的最小体验，能在第二个新目录复现。
- 将当前校准规划保存在源码 OpenSpec 路线图，以阶段事实组织后续工作；本地验收不冒充源码已公开或 G0 完成。
- 首批不增加产品依赖和受管文件，复用现有入口、检查和人类文档。

**Non-Goals:**

范围限制见 proposal；这里另明确：不复制第二份 Agent 协议、不制作新安装器、不实现会话启动服务、不把演示 S 任务升级为 M。三人招募、真实项目及跨工具验证均须到相应阶段再执行。

## Decisions

### 1. Minimal Option 与可行性

选择源码专用样例、已发布完整 v1.10.1 Full 包、两个可丢弃目标。包和协议保持现状，新增工作集中在样例、说明和受影响的导出属性。首个可观察成果是 B 仅凭项目输入与 A 的实时命令完成四组行为检查，并正确保存最终状态。

与仅改文案相比，该方案能检验实际接续；与新增安装映射、独立样例打包器或后台驱动相比，维护面较小。路线图校准属于规划，当前已经可以编写；实际演练与代码仍由后续实施完成。

可行性结论：现有管理器和入口支持此路径，无需改变受管布局或协议，允许进入实施；真实宿主遵从仍是待实际演练回答的问题。本轮未运行样例或 Agent，不把机制可用写成行为已验证。

### 2. 样例内容和目录

后续只新增以下源码文件，不进入 payload：

```text
examples/handoff-demo/
  README.md
  README.zh-CN.md
  fixture/
    AGENTS.md
    .gitignore
    labels.ps1
    test-labels.ps1
    openspec/
      config.yaml
      changes/normalize-demo-labels/
        proposal.md
        specs/label-normalization/spec.md
        tasks.md
```

样例函数 `Normalize-DemoLabels` 只处理 ASCII 标签：trim、忽略空白、不区分大小写去重、保留首次大小写和输入顺序。四组输入输出分别为：空数组→空数组；`[" Alpha ", "alpha", "BETA", "beta"]`→`["Alpha", "BETA"]`；`[" ", "", " a "]`→`["a"]`；`["b", "A", "b", "c"]`→`["b", "A", "c"]`。

先固定四组断言，再提供有明确缺陷的初始实现。原始 fixture 至少一组真实失败、退出非零；在可丢弃副本中正确修复后四组通过、退出 0。修复代码不回填源码 fixture。检查脚本正确处理空数组、单项及 PowerShell 管道展开，不依赖新测试框架。

AGENTS、OpenSpec 与脚本属于 Agent／机器输入，使用一致英文；两份样例 README 是专供人类阅读的说明，各自语言分开。fixture 不含 .ai、安装备份、宿主副本、完成勾选、旧 verdict 或预写修复结果。省去额外 expected 文件和配置表，预期结果直接放在指南与已有检查中。

### 3. 取得、导出与公开状态

源码样例采用含该样例的明确 Git 提交检出；完整包固定为可信 [v1.10.1 Release](https://github.com/calvinfungcn/engrelay/releases/tag/v1.10.1)，目标为新的、互不重叠的目录。安装显式使用 Full、SkillTarget none、WorkflowMode optional，通过目标内规范路径读取入口；宿主发现另测。

加入 `/examples/handoff-demo export-ignore`，保留 `/openspec` 与 `/docs/reviews` 的既有排除。不能指导从 GitHub 自动 Source code ZIP 取得该样例：[GitHub 说明](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)确认其使用 git archive，[Git 属性规则](https://git-scm.com/docs/git-archive#_attributes)说明 export-ignore 不进入归档。固定 Git 检出可保留被导出排除但已跟踪的文件。

候选尚未提交时，本地演练从工作树复制已记录哈希的 fixture，标为本地候选；不伪造含样例的提交号或声称公开下载已可用。正式提交准备时再固定包含样例的源码 SHA、复核固定检出与发行包配对、检查公开入口。样例说明可在源码内使用真实相对路径；随包的根 README／Quickstart 仅指向 GitHub 源码导航，并清楚区分候选与已公开来源，不能留下指向被排除样例的包内相对链接。此公开状态不回填为本次已发生的证据。

如需离线转交，样例使用已核对版本／文件指纹的源码文件夹，安装包另行原样转交；不增加自动下载器或另一个 ZIP 发行流水线。

### 4. A/B 执行与证据

1. 先用现有宿主能力验证一条最小实际调用能够对应输入、可得调用标识、返回和工作区产物，再扩大到第二个目录。该最小调用计入第一次真实演练，不额外凑次数。
2. 复制原始 fixture 到本次明确创建的目标，建立可检查 Git 基线并安装可信完整包。后续实施可在这些无远端的可丢弃目录使用 Git init、显式暂存及初始提交；身份使用单次命令参数或该临时仓库局部设置，源仓库 Git 只读。
3. A 收到样例需求路径和明确的 start-only 提示，只准备任务、映射与有效派发。写入后核对当前路由、能力建议、完整命令；按已有指南备份 A handoff，不覆盖已有备份。
4. B 是新会话，没有 A 聊天历史；可使用实际宿主的新会话或不继承父聊天的 Agent 调用，准确记录采用哪种。B 仅收到项目路径、continue 入口和实时完整 Operator Command。不能用同会话更换角色名称或脚本填文件替代。
5. B 按真实角色修复，运行四组检查、维护样例唯一 tasks 与最终 handoff。S 自检关闭不冒充独立审查；源仓库 M 审查另行进行。行为结果与最终结构检查分别保存。
6. 第二次从原始 fixture 进入另一个新目录，不复用已修复代码、关闭运行态或已完成清单。修订后重试另记，原失败保留。

沿用 Quickstart 的 Windows、Git、pwsh≥7 前提；EngRelay 不安装 OpenSpec CLI。预置 OpenSpec 文档是需求权威，并非声称安装了 CLI。宿主已触发的强制 Skill／工具前提仍需遵守，实际所需额外工具如实记录在准备项；没有时只暂停依赖动作，不偷偷改协议或安装全局工具。

原始会话、日志和运行态放 `.ai/growth-first-handoff/` 的具名结果／runs 下。公开 `docs/reviews/improve-first-handoff-trial/trial-evidence.md` 只给脱敏摘要、固定输入版本或候选哈希、可得宿主／模型设置、实际尝试、检查退出与限制；可用原始来源留在本地并以指纹对应。不公开私人路径、账号或聊天，不制造宿主标识。模型等待与复制命令均计入观察，不作零人工或 token 节省承诺。

### 5. 检查、批次与审查

| 变化 | 最小检查与范围 |
| --- | --- |
| 初始样例／可丢弃修复副本 | 原始非零、修复四组通过；fixture 未被修好；初始无运行态；唯一点号任务对应 |
| 双语 README／Quickstart／样例指南 | 实质语义、语言互链、现存本地链接、取得方式和三目录边界；不新增措辞匹配测试 |
| .gitattributes | 对样例目录核对 export-ignore，在无远端的一次性小型 Git 树实际归档，验证样例及已有排除均生效、无关控制文件保留；这只是边界夹具，非最终源码发行导出 |
| 真实 A/B | 两个新目录、各自真实调用输入／返回与 B 上下文隔离、行为结果、A 备份与最终状态；不把结构 exit 0 当作 Agent 遵从 |
| 包边界 | 官方 1.10.1 包保持完整与不可变；确认 payload／管理器／受管集合未变化；不因文案跑全部历史套件 |

规划校准在本轮完成，不算实施验收。后续只用同一批次推进样例、指南及两次演练；所有实现任务只在 tasks.md 勾选。风险 M、当前累计 0、默认总额 3。没有复杂度例外，首批具有可观察结果，因此不强制额外 Design Review；按正常路径在完整交付后进行一次独立聚合 Code Review，必要修复及复核共享累计额度。

独立审查可将架构、双语、行为和证据一并覆盖；不得由实现者自审。默认交付评分沿用现有规则，不为本样例增加新评分。Reviewer 在通过后核对最终映射和 handoff 再关闭；外部 G0、公开固定提交仍按实际状态保留后续入口。

### 6. G0 与后续路线图

路线图与双语样例指南提供简短记录口径：匿名编号、版本／环境、首次还是重试、标准操作与额外救援、结果、核心与完整耗时、最难步骤／再次使用意愿。没有数据就写未测；不要求填入未知 token、费用或额外遥测。

G0 沿用内部两次复现、三位未参与设计的目标用户首次尝试至少两位独立完成，且没有关键内容损坏、越权或证据造假；十分钟目标另记。当前仅交付协议，不联系用户。内部通过可结束本变更的本地映射，但 G0 仍为待验证。

有限 Phase 1 先验证一次编码中途新会话接续与一次符合风险要求的独立审查，再尝试一个有实际用户的跨工具组合；条件不足就保留具体限制。F3 优先独立最小修复，F4 必须在受管路径新增／退役的发行前解决；本次不新增受管路径，因此它们不是本次样例的阻塞门槛。

建议实施按 1～2 个会话、6～10 小时有效投入作时间盒，模型等待与外部招募另计，不把估算作为路由或验收门槛。上游比较最多 2～3 小时且已完成本轮必要范围；发现需要新工具平台或明显超预算时，优先保留样例／指南和一个已成立的最小真实调用，再说明缺口及更小选项，不能把部分完成改写成两次演练通过。

## Risks / Trade-offs

- 双来源获取增加步骤 → 复用已要求的 Git，固定源码／包配对，提供经过核对的离线文件夹，不新增打包服务。
- 未发布候选没有公开样例 SHA → 本地哈希取证，公开取得状态留到适用提交准备，不改写历史或编造链接。
- Agent／宿主能力不稳定 → 先确认最小实际调用；缺失证据只阻断对应验收，不把说明增长当修复。
- 额外上下文与流程负担 → 不改规范 Skill，不复制协议表，不增机器字段；一个固定 S 样例和一次 M 聚合审查即可。
- 排除规则误伤其他文件 → 仅排除具体样例目录，保留原规则并用有无关控制文件的真实归档检查。
- 外部试用被误作已完成 → 源码本地交付、公开取得、G0 三层状态分开，首次失败和额外救援保留。

## Migration Plan

这是源文档／样例增量，不迁移已安装配置。实施先固定样例行为，再接指南、完成真实演练和独立审查。下一次获准的源码提交／发行准备才固定公共样例提交、从实际提交干净导出、更新 staging 清单并验证受影响包字节；当前根 snapshot、版本和 CHANGELOG 保持现行发行事实。

回退范围仅为本次新增源码样例、说明入口与定向排除；保持已有排除及产品契约。演示项目如需卸载沿用对应包的受保护 Uninstall，不删 manifest 或强行覆盖；保留真实失败与审查记录。

## Open Questions

外部三人试用的人员／日期、后续跨工具组合、授权提交后的样例 SHA 与未来发行版本待相应阶段确认；不影响当前本地方案和任务分解。真实宿主遵从与费用收益仍待观察，不能由本轮规划回答。
