# Design

## Context

动机见 [proposal](proposal.md)，行为约束见两份 [package delta](specs/collaboration-package/spec.md) 和 [profile delta](specs/workflow-profiles/spec.md)。这是已关闭 Lite／Full 整合后的独立 M 级改进，当前基于本地1.10.0候选；本文件不是新的实施清单。

已核对的复用依据：

| 现有位置 | 观察 | 最小处理 |
| --- | --- | --- |
| payload/docs/ai-collaboration/agent-prompts.md 的 Common Preflight | 已规定同会话复用未变资料、必要时刷新，并禁止反复粘贴整本手册 | 保留这一权威，其他入口引用并对齐，不另造缓存规则 |
| canonical start／continue Skill 的 Read First | start 提前列出条件性需求分析材料；continue 对 schema 仍为整文件引用 | 按实际触发条件和相关章节定位，保持激活／恢复／预算语义 |
| Full README、handoff／response模板、Code Reviewer及Verification Reviewer | 已有证据引用、落盘回读、只读返回和独立性规则；尚无本次交付评分 | 原地增加短示例／评价指引，不改状态机和验证器 |
| Lite RULES、project-config／queue模板、README双语 | 已有短入口、项目自有配置及串行队列；偏好字段和简短评价示例不足 | 在现有文件补可选偏好和简短说明，不增加 Full 必读 |

结构代码发现先使用本仓库知识图；已直接核对上述函数及相关非代码契约。两份本地备忘录只用于设计输入：账单未复算，不把一次观察当费用因果；旧30/32等历史状态不覆盖当前已归档32/32及原审查记录。

## Goals / Non-Goals

**Goals:** 让既有入口较容易按需执行、让取证与勘误有可照做的最小范例、让用户在已有审查中看到可解释的本次交付评价；保持旧配置、当前角色权限和最终交接保护。

**Non-Goals:** 不新增安装路径、脚本、机器字段、第三种配置、自动调度、评分调查或统一账本；不以预算、单文件或分数降低风险／验收。范围严格采用已确认的收缩方案，不把备忘录中的其他建议转成必做条件。

## Decisions

### 1. 原地对齐入口，不建立第二份手册

只在canonical Full start／continue和公共角色指引修正条件读取／章节定位；真实边界刷新当前任务、交接和受影响输入。新Agent、上下文缺失、资料变化或疑问时重新读取；当前适用项目指令和已触发Skill的加载要求优先。不要求每次检查参考资料哈希，也不强制每个S任务另开会话。

大日志在产生时外置，工具返回摘要、实际结果和路径。Full的操作示例放在现有operator-guide双语版本；Lite只在自身RULES／README中保留必要短说明。替代方案是新增CHEATSHEET或复制全文规则，会扩大来源集合和同步成本，故不采用。

### 2. 取证与收敛只补具体做法

现有指南以一个小示例贯穿调用→输入→返回／产物→实际检查，并用固定的“六次启动误写七次”实例说明启动、后续输入、失败、协调和汇总不可混算。示例须明确哪些是演示数据，不冒充真实执行。方法已知可行或验收不要求真实Agent证据时，不追加预演。

完全只读返回沿用现有模板和来源匹配要求；发布者保存原文后只规范化无歧义格式，技术结论有歧义不能代改。新增勘误不改旧报告，修复或统计检查只覆盖受影响输入；原有普通accepted要求和审查额度仍生效。替代方案是通用日志采集／认证／汇总工具，当前收益不足，暂缓。

### 3. Lite配置和队列保持可选、原格式

在现有配置模板加一小组可选偏好及已核实的评审启动命令／限制／隔离示例。偏好不能充当能力证明、执行许可或自动调用指令，留空不阻塞；指南明确既有项目实例由项目维护，不能通过升级覆盖或强制补齐。

队列不加列或固定多项总结，现有evidence单元格可放一句结果及稳定链接。整理仅给人工／既有授权下的示例：先保证依赖仍可解析，保留暂停快照和已被正式记录引用的证据路径；不设20条自动触发和新迁移脚本。

### 4. 评价放在已有结论，不建设评分系统

Full的短口径维护在现有README相关段落，Code Reviewer、Verification Reviewer和review-round模板指向它；Lite RULES保留等义自包含短定义，不要求加载Full手册。实施评价由已有Code Reviewer负责，修复评价由已有独立复核者负责；Lite使用对应Reviewer。不评价其他角色，不增加专门评分会话。

采用delta中的1–5分和无法评分，优先一段文字容纳分数、发现引用、主要原因和有必要的建议；不设强制子分、加权公式、阈值审批或新解析字段。已有Review元数据／内容指纹定位受审版本，无需另建评分记录。最终回复只复述短评价，handoff不复制评分表。

输入不清、环境限制或审查依据变化不自动归咎实施者；无法区分时保持未知。高分不是PASS，低分不自动提高C档或换模型；历史无评分不迁移，本次遗漏在已有保存步骤补充，不发起新的业务复核。

### 5. 两组实施，一个有限验收范围

两组工作分别是入口／证据示例，以及Lite便利性／评分反馈；共同交付一个可检查的用户行为：按轻量入口接续并从已有独立审查取得可解释的反馈。可在一至两个实施会话完成，不按文件拆批、按组审批或清零。正式清单只在[tasks.md](tasks.md)。

先完成每组实际差异／引用／术语一致性检查。行为代表范围仅一个S接续、一个M审查和固定脱敏修复输入；S使用GUID虚构目录中的实际Agent调用及相关规则镜像，命名输入、返回、产物和最终状态，不能只生成预填handoff。M优先复用本变更本来就要发生的独立代码审查，派发时明确其亦为代表场景，已有verdict只计一次。固定修复实例只核对评价口径，不伪称发生实际修复复核。

代表场景可使用当前可用维护宿主；Lite旧配置、队列和自包含指引另用固定输入核对。不从这两个样本宣称全配置／宿主遵从。没有实际运行能力或输入／结果不完整时，相应必需任务保持未完成，而不是用静态示例代替。除了正常独立审查不额外开模型／宿主矩阵、H演练或费用A/B；token和成本不可得时保留未知。

### Feasibility and Design Review Decision

端到端结论：可按最小方案继续。必需行为均能落在已有文档／模板／角色出口，已有结构校验和项目配置保留能力可复用；无需新增依赖、服务、API、安装状态或权限。首个可演示结果是S任务从明确入口接续、保持权威并正确保存下一状态；评分可在本来就要发生的M独立审查中观察。

Design Reviewer：**no**。当前没有架构／数据／认证／归属边界的复杂度例外，建议性评价不形成新机器协议或调用方API；采用正常M独立代码审查即可。此决定不是自审PASS；以后若触及投影、校验器、机器字段或无法形成可演示结果，应回Chief Designer重新核定，而不是继续扩大实现。

本批尚无verdict，累计0／默认3，正常路径是实现→独立代码审查→需要时一次集中修复及独立复核。两个工作组和代表场景不重置计数；原已关闭8/8及所有历史Review不变。当前没有人类独占前置，资料和本地规划工具可用；产品行为尚未实现或演练通过。

## Risks / Trade-offs

- 新说明反而增加读取 → 优先原地短指引，长示例按需；不把备忘录加入日常必读，不用新台账证明缓存。
- 复用导致陈旧输入 → 保留新Agent／缺失上下文／变化／疑问的刷新条件，真实边界检查和恢复规则不变。
- 分数主观或被当模型能力结论 → 限于本次现有发现，允许无法评分，区分责任来源，不做跨任务排名或自动调整模型。
- 整理破坏依赖／历史 → 不自动搬迁，保留稳定任务ID和正式证据路径，暂停项仍用自己的快照。
- 样本和文案不能证明宿主遵从或费用收益 → 独立列出真实调用、固定实例与未测边界；不要求凭空补齐成本。
- 规则文案改变可能出现冲突 → M独立审查聚焦权限、闭环和实际差异，不为文字匹配新增脆弱测试；仅在有相关行为变化时扩大检查。

## Migration Plan

本轮只规划。实施优先修改现有Full Skill／规则／审查模板、operator-guide双语、Lite RULES／config／queue／README双语，以及必要的根README／CHANGELOG双语未发布说明，不添加部署文件或改manager／validator。

旧配置可自行按需增加偏好；旧队列格式、未评分报告和原关闭记录不回填。未来获准准备发行时按现有干净暂存流程重建完整snapshot；开发期间不更新根snapshot，也不修改已有1.10.0候选ZIP或旧版可信指纹。文本回退保留已产生的Review／评分原件和项目配置；没有数据迁移或自动回滚。
