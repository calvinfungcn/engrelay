# Proposal

## Why

用户目前需要在 start 与 requirements 之间自行选择入口；第三方方法有值得吸收的更新，但整包覆盖会破坏现有权威与角色边界。人类使用和维护说明只有部分中文覆盖，且数份英文文档夹有中文正文，增加使用成本。

## What Changes

- 将 ai-collab-start 作为推荐通用入口，按业务歧义条件复用已有需求分析职责；保留 requirements 的名称、路径及显式需求讨论能力。
- 从固定的 Superpowers v7.0.0 与 CE v3.30.5 参考中筛选适用方法，更新本地审查/调试规则并保留来源、许可及既有独立性；不导入整套上游生命周期。
- 为专门面向人类的使用、采用、宿主、贡献、维护、变更和许可说明提供独立中英文版本与导航；英文 Agent 契约只清理夹杂的中文说明，不增加中文副本。
- 为新增部署文档维护精确的历史布局转换登记和聚焦归属验证，保留已有七个 Skill、机器字段、模板、输出及管理器行为。
- 保留历史审计原件、开发指南英文 Agent 提示词及许可证原文。没有破坏性入口删除，也不授权提交、发布或部署。

## Capabilities

### New Capabilities

无；复用现有工具包能力边界。

### Modified Capabilities

- `collaboration-package`：扩展稳定入口的条件澄清行为；约束选择性上游方法同步、人类文档双语分离，以及新增文档的受保护部署与升级。

## Impact

- 规范来源：payload 下 start/requirements、CE 审查/调试 Skill 及必要的共享契约；生成宿主副本不编辑。
- 人类文档：根双语 README、贡献/开发/变更/许可说明、源码导航；payload 下采用与宿主说明、新的操作者指南和既有双语示例。
- 安装兼容：scripts/supported-layouts.json 登记新增文档；scripts/manage.ps1 的运行算法、归属保护及输出不改。
- 验证：入口条件场景、上游方法适用性、译文和链接、精确新增路径、一次性安装/升级/卸载夹具；不重跑无关历史套件。
- 不引入依赖、本地化框架、自动上游更新、外部模型传输、运行时编排或新的实施权威；tasks.md 是唯一实施清单。
