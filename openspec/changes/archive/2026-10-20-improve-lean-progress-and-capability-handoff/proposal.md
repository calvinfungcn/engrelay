# Proposal

## Why

现有规范已覆盖最小设计和成果可见性，但缺少统一、可选的粗估与成果表达约定，照搬团队原稿会增加填报和误报停滞。C1–C5 已要求在新 Agent 派发中显示，实际仍有漏写报告，且双语根 README 的“可增加”与核心规范的必填输出语义不一致。

## What Changes

- 复用现有最小授权、精益设计与审查规则，只对可证实缺口作局部解释；不复制一套防过度设计流程。
- 在既有区块定义可选修改规模与投入估算、成果/证据/剩余工作摘要；不要求小任务估算，不以 LOC、百分比或交接次数决定风险、验收和路由。
- 在现有交接输出及回读步骤提醒核对能力首行与最终回复，修正双语公开说明的可省略歧义；保持角色默认表、动作适用范围及旧记录兼容。
- 更新必要双语说明、Unreleased 记录及源码跟踪入口。自动统计 P2 标为待决定，不纳入本次交付。
- 保持 validator、模板机器结构、安装管理与恢复算法不变；不新增告警、角色、审批、依赖或运行态文件。

## Capabilities

### New Capabilities

无新增能力目录。

### Modified Capabilities

- `collaboration-package`：补充既有交接中的可选估算及证据化成果语义，强化新 Agent 派发能力提示的输出完整性与双语说明一致性。

## Impact

主要涉及 `payload/docs/ai-collaboration/README.md` 的现有进度/度量段落、Common Preflight、三个 canonical 入口 Skill 的输出说明、handoff 模板注释与必要 schema 引用；以及双语根 README、CHANGELOG 和 OpenSpec 导航。保持现有机器路径、锚点和部署文件集合。

变更风险为 M，保留独立代码/协议审查。新增提示可能增加上下文，因此共享定义集中维护、入口仅短引用；模型仍可能漏写，实际抽查不宣称宿主强制保证。规划及实施均不授权提交、发布、安装到真实项目或修改全局设置。
