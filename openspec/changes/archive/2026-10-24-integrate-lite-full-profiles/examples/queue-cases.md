# 顺序队列固定场景

第一期只核对逻辑输入与预期，不执行业务任务。队列状态不是第二份 OpenSpec 实施清单；已有正式范围时每项引用原 tasks.md。

## 固定输入

| ID | 批准与验收输入 | 前置 | 当前事实 |
| --- | --- | --- | --- |
| T01 | 已批准离线规则修订，验收引用其任务记录 | 无 | 做了一半，下一步需范围外付费接口决定 |
| T02 | 已批准独立文档修正，有明确验收 | 无 | 尚未开始，目标文件与 T01 不冲突 |
| T03 | 已批准依照 T01 最终规则生成说明 | T01 accepted | 尚未开始 |
| T04 | 仅有人建议优化，无负责人范围确认 | 无 | 不在已批准执行集合 |
| T05 | 已批准第二个独立小任务 | T02 accepted | 尚未开始 |

## 预期序列

1. T01 暂停前，先把任务、当前事实、累计数、决定和恢复点写入 tasks/T01-handoff.md 并回读，再更新 queue 的待决定引用；无可写证据时不能直接切任务。
2. 下一可取项只有 T02：不依赖 T01、已批准且目标不冲突。新的 live handoff 只能描述 T02，不覆盖 T01 的暂停快照。
3. T03 的前置未满足，保持等待；T04 未批准，不执行。
4. T02 的验收和适用自查／独立审查完成后才记 accepted；归档其真实交接并核对队列，再取 T05。不能只因代码写完就提前释放 T05。
5. 负责人作出 T01 的适用回复后，负责 Agent 读取 T01 快照和最新权威，恢复同一任务及原累计数。T01 最终 accepted 后 T03 才可取。

## 正反场景

| ID | 变化 | 唯一预期 |
| --- | --- | --- |
| Q01 | 固定输入不变 | 保存 T01 后执行 T02；T03、T04 不执行 |
| Q02 | T02 实际修改 T01 尚未确定的同一规则 | T02 也受影响，不能假称独立继续 |
| Q03 | T01 仅有后续验证的中性环境预告，离线步骤可继续 | 不进入待决定或环境暂停；原 Executor 继续 |
| Q04 | 当前任务网络故障，有限重试未恢复 | 记录环境暂停、恢复条件及自己的快照；只继续不依赖该环境的已批准任务 |
| Q05 | T03 与 T05 形成相互前置 | 受影响项不可取，说明循环；不添加图调度器，不阻断其他独立项 |
| Q06 | T02 必须修 F02 未经独立复核 | T02 不 accepted，T05 不释放；不能挪 F02 到待决定掩盖未满足验收 |
| Q07 | T01 达到三次累计 verdict 后仍有问题 | 等待负责人的适用有限授权／处置，不因转做 T02 而清零 T01 |
| Q08 | T02 已验收，另有不属于其范围的可选新需求 | 新需求明确跟踪而不伪装成 T02 已交付内容；可关闭 T02，不能把范围内未满足项用同样方法移走 |
| Q09 | 宿主进程在 T02 continue 后退出 | 状态仍表示可接续；重新接入 Agent 后按最新授权继续，不承诺自动唤醒 |
| Q10 | 有两份不同任务的暂停交接，数字分别为 T01 r9、T02 r4 | 先按任务 ID 和队列引用选择，不跨任务比较最大 revision |

“已完成”记录只需成果、改动、实际检查和审查引用，工具／模型信息按已知事实写；不为队列增加积分、百分比或常驻统计系统。历史归档保留引用且不覆盖同名文件。
