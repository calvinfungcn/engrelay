# Proposal

## Why

归档前完整独立审查是合理的质量保障，但现有规则对通过后的适用输入、局部修复复核、关闭后追加请求及归档核对之间的边界说明不足。真实维护经历还暴露了旧入口证据误作新验收、审查产物再次带入私有标识的问题，造成错误通过和额外返工，需要在现有机制内补清边界。

## What Changes

- 保留负责人明确要求的归档前完整独立审查，完整覆盖授权验收、最终差异、兼容性、实际证据、说明与交付隐私；通过后按变化决定复核范围。
- 将版本／入口／输入／环境／结果对应与报告自身脱敏纳入既有审查；缺失如实标为未验证，真实新缺陷或失效证据可扩大复核。
- 区分未关闭的原验收、关闭后的单次追加审查、新缺陷修复及归档核对，关联旧历史，不以换批次获得新额度；单次审查授权不扩成三轮自主修复。
- 归档核对以实际变化定级，检查规范同步、文件完整性、任务／索引和隐私；复用匹配证据，通过后结束。
- 保留现有交付评分，仅在已有证据足够时简述问题来源；Full 集中定义、角色按需引用，Lite 自包含，人类指南保持双语。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `collaboration-package`：明确完整审查与复核边界、证据对应及产物隐私、关闭后有限授权、归档收敛和评分归因。
- `workflow-profiles`：使 Lite 用自身短规则表达相同审查／授权边界，保留三类职责、轻量输入和配置隔离。

## Impact

拟修改既有 Full README／角色／流程／审查模板，以及 Lite RULES／任务模板；双语根 README、Full operator-guide 与 Lite README 提供对应人类说明。仅使用已受管路径，不改安装器、校验器、入口 Skill、机器字段、受管清单或根发行快照。

在一个 M 批次完成规则和五类虚构场景检查，复用既有独立聚合审查；不新增评分平台、全量宿主矩阵、运行时引擎或普遍归档审批，不导入真实项目资料。具体路径、最小方案、副作用、额度与验收方法见 design；tasks.md 为唯一实施清单。
