## Findings

### CR-01：入口把聚合整理的触发条件扩大到所有后续接续

- Priority: `must-fix`；Status: `open`。
- 位置：`payload/docs/ai-collaboration/skills/ai-collab-continue/SKILL.md:119`、`payload/docs/ai-collaboration/agent-prompts.md:93`、`payload/docs/ai-collaboration/workflows.md:37`，以及两份角色实现摘要。
- 问题：这些入口仅以同一未完成验收已有两次往返为条件，要求在继续前整理；没有要求确实计划下一次正式修复或复核，也没有排除已经整理且尚未发生两次新往返的情况。共享规则 `README.md:719` 则明确包含这两项限制。
- 影响与复现：一次整理后，尚未新增两次往返而继续同一角色的安全开发或局部检查，入口仍会要求再次整理；这与 delta 的“整理不反复触发”场景冲突，也可能重新制造本任务要减少的重复流程。
- 修复方向：使所有适用摘要与 continue 的触发、再次触发条件一致，保留有限授权、停滞分析和人工接力。

### CR-02：机械格式合并规则遗漏强制提前审查例外

- Priority: `must-fix`；Status: `open`。
- 位置：`payload/docs/ai-collaboration/agent-prompts.md:97`、`payload/docs/ai-collaboration/agent-prompts.md:861`、`payload/docs/ai-collaboration/workflows.md:1097`，及对应公共摘要。
- 问题：这些摘要直接指示机械格式修正与相关修改合并、无需专门正式轮次；共享规则 `README.md:981` 和 delta 仅允许不存在必须立即独立复审等适用门槛的情形合并。
- 影响与复现：若项目或用户明确要求某类格式变更后立即独立审查，上述无条件指示与该前置要求冲突，可能延迟或省略要求的审查。显式检查和独立性是现有授权边界。
- 修复方向：在适用摘要中保留“无强制提前或立即复审要求”条件，并用有／无该门槛的虚构场景核对，不增加默认审查。

### CR-03：单角色停止规则在没有后继角色时仍要求人工转交

- Priority: `must-fix`；Status: `open`。
- 位置：`payload/docs/ai-collaboration/README.md:1347`、`payload/docs/ai-collaboration/agent-prompts.md:100`、`payload/docs/ai-collaboration/workflows.md:39` 及相应入口摘要。
- 问题：只要用户要求当前角色完成后停止，新增规则就要求准备后继角色交接并放置人工转交提示；delta 的该场景实际以前提“下一工作由另一角色承担”为限。既有干净通过的 `close` 路由则要求 Next role 为 `none`，没有 Operator Command。
- 影响与复现：用户要求独立 Code Reviewer 本轮完成后停止，而审查干净通过、无需后继角色时，新增通用指令仍要求后继角色和人工转交，与正确关闭互相矛盾。
- 修复方向：将人工派发及顶部提示限定于实际需要向另一角色 `dispatch` 的边界；有效的 `close` 与真正等待继续使用各自原有规则。
