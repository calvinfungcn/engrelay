### CR-01 — H 未指定下一角色输出，尚不能证明完整响应交接

**位置与事实。** 已保存 H 响应第 15 行明确为 `Next output files: none`；原始会话最终回复的 H 正文也是同一值。其 Operator Command 的 Output 只要求泛称 review verdict/response，没有指定正式 review record、index、handoff 或一个具名响应工件。它同时派发 Code Reviewer 执行正式 M 审查。

canonical `README.md#routing-contract` 的 Agent dispatch 分支要求非空 next input/output files；`handoff-schema.md#response-handoff-fallback` 要求列出 required paths or response artifacts；`handoff-schema.md#general-rules` 要求正式派发明确每个可写输出。模板里的 `<workspace file path or none>` 是各动作共用占位符，不能覆盖 Agent dispatch 分支。只读 fallback 可以交付具名响应工件，无需虚构文件写权限，亦不能因只读把正式审查的输出责任消掉。

**影响与边界。** H 的能力首行 C3、最终回复中的同档位、完整命令主体、未持久化说明均有可追溯证据；本轮不否认这些已验证部分。但 `2.1` 明确要求完整响应样本，`3.1` 要求文件/响应代表组合，当前 H 仍未满足输出归属约束。证据表将它概括为完整通过，不能据此完成这两项的全部验证或 CR-01。这是现有验收的证据缺口，不是已证明的 canonical 产品缺陷，也不要求模型零遗漏。

**最小处置。** 保留原 H 及会话，不重写为成功。优先复用可取得的真实、完整且有效的既有响应输出；没有合适原件时，仅补一个新的 response-only Code Reviewer 派发样本。样本应允许符合实际权限的具名 review/response 输出，在 Routing 和 Operator Command 中一致指定；直接读取完整 canonical 分支，保留实际输入、生成响应和最终回复及哈希。核对 C3 首行与最终复述、独立性、输出责任、未落盘说明和命令完整性。只读响应可人工核对，不强求将响应伪装成文件通过 validator。不重放 A–J、安装/恢复套件，不要求改产品、validator、模板或新建测试框架。按真实证据对账 tasks `2.1/3.1`；不足时保留未完。
