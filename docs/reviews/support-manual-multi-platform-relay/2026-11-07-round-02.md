## Findings

### FR-01 — must-fix / P1：纠错结论与升级日志矛盾，Full 漂移拒绝未通过（证据有效性缺陷）

定位：`correction-result.md` §2 PR-01（"Tampered drift test: candidate upgrade rejected with exit 1; zero writes"）与 `correction-scenarios.md` 场景 9 表格（`0 / 1`, PASS）；`tasks.md` 4.1 已勾选完成。

实际日志 `correction-upgrade-check.log` 第 72～78 行原文：

```text
Full Drift Tampering Check:
  Tampered AGENTS.md (new SHA256: acc90e90b0a728cdae591f6e8c7b39b38a19f1d4cb4ba88607e52e9f6)
  Upgrade attempt after drift exit code: 0 (expected: 1)
  ...
  Zero writes to tampered file verified: False
```

即：Full 侧漂移篡改后升级仍以 exit 0 通过（期望 exit 1），且篡改文件存在写入（`Zero writes: False`）。Lite 侧同文件第 102～120 行确为 exit 1、零写入 True，通过。

结论：PR-01 的 Full 漂移拒绝证据为失败，但纠错总结与场景表将其记为通过。属于伪造结果（falsified result），按角色规则为证据有效性缺陷，必须阻塞。`tasks.md` 4.1 的完成勾选因此不能成立，需回退或附条件重验。

最小处理：查明 Full `manage.ps1 Upgrade` 对 `AGENTS.md` 根级受管文件漂移不拒绝的原因（与 Lite `docs/engrelay-lite/RULES.md` 路径行为差异）；修复后在隔离夹具重跑 Full Clean＋Drift 两段并记录真实命令、退出码、SHA256；以真实日志为准重写 `correction-result.md` §2 与场景 9 分类的 Full 部分，保留历史错误作勘误；4.1 在证据成立前不得标完成。

### FR-02 — must-fix / P2：场景 9 PASS 越界，分类建立在失败证据上

定位：`correction-scenarios.md` 场景 9（`Result: PASS`，`Verified by Test (Clean upgrades exit 0; drift tampering rejected exit 1 with zero writes)`）。

由于 FR-01 的 Full 漂移实际为 exit 0／有写入，场景 9 的 "0 / 1 PASS" 表述不成立。Lite 部分成立，Full 部分不成立，整体不得记 PASS。分类中 "Verified by Test" 对 Full 漂移段落为错误归因。

最小处理：场景 9 拆分为 Full/Lite 两行分别记录实际退出码与零写入结果；Full 行记为 FAIL／未验证并引用 FR-01；PR-02 的场景证据在 FR-01 修复前不得作为 4.2 完成依据。
