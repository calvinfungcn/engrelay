### 一致性与可行性核对

- proposal、design、增量 specs、tasks 互相对应：写权限与持久化（spec 1–2）→ 任务 2.1；来源链接 fallback 与恢复（spec 3–4）→ 任务 2.2；可选预期校验（spec 5）→ 任务 3.1–3.3；双语公开说明 → 任务 2.3；独立 M 代码审查与关闭 → 任务 4.1–4.2。九个任务与 `.ai/current-task.md` 的映射 ID 一一对应，未发现第二份实施清单、新 Routing 字段、新动作/状态或新状态库。
- 设计引用的源码事实已逐项核对为真：validator 参数仅 `WorkspaceRoot / CurrentTaskPath / HandoffPath`；`Get-FieldValue` 返回首个匹配；`State revision` 只校验语法（`^[1-9]\d*$`）；`Get-MarkdownStructure` 提供围栏感知的 `UnfencedText`，现有 `Human Action Required` 检查已用同法限定 Routing；测试 helper 使用 GUID 临时根、真实子进程、退出码与诊断子串断言及 `CaseFilter`（无匹配时静默返回，故任务 3.3 要求记录匹配案例数是必要的）。
- 权限问题的根因属实：`agent-prompts.md` Implementation Engineer 输出要求给出“允许必要产物，或显式选择严格只读”，生成的审查指令可落入后者；两个模板仍写“Read-only permits artifact writes only when explicitly authorized”，没有要求列出具体产物；schema 的 fallback 只写“handoff 保持过期”，没有持久化来源匹配依据。设计的“逐项列出审查记录、索引、handoff”正对应该缺口，且不扩大到任意文件。
- 角色与独立性：恢复复制的是来源角色已作出的决议，不新增 verdict、不改写来源角色/Agent；恢复者先持久化再自评下一角色资格，与既有“下一可写角色须先持久化响应交接”的 schema 句一致，没有授予自审路径。
- 优先级：已关闭、真实等待、额度耗尽无有限授权、独立性均在 spec 的专门场景中先于恢复；旧记录不强制回填。
- 比例：五个可选参数已由 `current-task` 明确为公共 CLI 契约例外；`ExpectedBatchId` 强制与其他参数同绑可防跨批误判，`ExpectedStateRevision` 是同动作/角色/计数下区分旧新状态的唯一手段；脚本保持只读、不扫描 review/index。无后台进程、数据库、迁移或新依赖，成本与已确认缺陷相称。
- 限制表述诚实：不宣称原子性、全局最新、真实性认证、自动唤醒、宿主遵从或业务验收；任务 2.1–2.2 的演练明确区分“演练”与“真实宿主遵从”。
